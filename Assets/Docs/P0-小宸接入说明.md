# 小宸 P0：输入、镜头与基础 UI 接入

日期：2026-10-09。个人分支：`xchen/feat-p0-player-ui`；目标分支：`master`。

## 范围与协作通知

当前 master 的文档已经重排，旧分工的输入 17、镜头/UI 19—20 对应 **21-InputSystem、23-CameraSystem、24-UISystem**。本次不修改任何 Core、Actor、地图、移动、状态、目标系统内部实现，也不决定机关、窄路和放置规则。

这是发给小茶、小智的接口接入通知，先通过 Draft PR 请求另一位开发者审核，再提交依赖此契约的实现：

1. 输入沿用既有公开方法，落实 `PlayerInputSnapshot` 和 `PlayerCommandSubmittedEvent`。Move 传 Vector2 方向，PrimaryAction/Attack 传屏幕像素位置；不指定 Actor，也不执行伤害。取消事件的 IsUserRequested 为 false 时，消费者清除旧移动/待处理操作。
2. 镜头的概念 ScreenPosition / WorldPosition 首版明确为 Vector2 像素 / Vector3 世界位置；MapManager 负责人把公开边界结果构造成 CameraBounds 后 SetBounds，避免双方发明不同共享空间类型。
3. UI 增加 `IUiSnapshotSource` 接入契约。目标/Actor 的领域查询仍以其文档为准；关卡适配层负责调用并组装显示快照。计数未接入时显示 `--`，胜负只读取 LevelManager 的已确认阶段。
4. `SetInputMode`、`UISystem.SubmitCommand` 保持设计文档的 void 签名。UI 接受结果通过 `UiCommandSubmittedEvent.Accepted` 观察。
5. 补充 `com.unity.inputsystem@1.7.0`，不更改其他包和已有新版输入设置。依据、影响和回退方式在 21 文档。

具体参数、失败和生命周期语义以三个系统文档及 99 全局 API 表为准。PR 审核前这些新增数据契约可调整；调用方不要依赖私有字段或测试夹具。

## 关卡组合

测试资产在 `Assets/Game/Tests/PlayerPresentation/`。正式关卡接入时，创建一个带 `PlayerPresentationRoot` 的场景对象（自动要求 InputSystem 与 UISystem），和一个带 CameraSystem 的正交 Camera，然后由关卡组合代码明确初始化：

```csharp
// 示例放在团队自己的关卡组合层，manager/camera/source 均显式获取。
presentation.Initialize(levelManager, cameraSystem, uiSnapshotSource);
cameraSystem.SetBounds(new CameraBounds(mapMinimum, mapMaximum));
```

也可在 Inspector 指定 LevelManager、镜头、视图和实现 IUiSnapshotSource 的组件；Bootstrap 中的 LevelManager 跨场景保留时，组合组件只在 Start 查找一次。先初始化镜头，再初始化 UI 和输入；UI 缺失不影响玩法。

真实场景应使用 `InputSystemUIInputModule`，不要同时挂旧 StandaloneInputModule。默认 HUD 可运行时创建，支持替换成自定义 BattleHudView 和指定字体。不得把 BootstrapP0Player、PlayerPresentationFixture 或 TEST_ONLY_ResultControls 放入正式场景。

## 小智 / Actor 负责人的输入接入

```csharp
// 在接入组件启用或当前关卡初始化时：
commandToken = input.Subscribe<PlayerCommandSubmittedEvent>(OnCommand);
cancelToken = input.Subscribe<CancelInputEvent>(OnCancel);

// OnCommand 内：
// Move -> 选定受控对象 -> 自己的公开移动/行动请求。
// PrimaryAction -> camera.ScreenToWorld(command.ScreenPosition) -> 自己的公开行动请求。
// Attack -> 自己的公开攻击意图入口；不可直接扣血。
// OnCancel 无论是否用户发起，都清除旧方向和待处理操作。

// 禁用或关卡销毁时：
input.Unsubscribe(commandToken);
input.Unsubscribe(cancelToken);
```

Move 运行中每帧提供非零方向，停止提供一次零方向；事件消费可以缓存方向，FixedUpdate 是否/如何提交 MovementRequest 由移动系统的公开契约决定。消费者也可在 LateUpdate 读取本帧快照，多消费者不会互相消费边沿。没有约定正式角色控制方式，暂不从输入层选 Actor 或假设点击即放置。

## 小茶的目标和数量显示接入

由接入组件实现 `IUiSnapshotSource.ReadSnapshot(LevelContext)`，调用 ObjectiveSystem、SlimeManager、EnemyManager 的公开快照 API，把目标描述、存活数、失败原因转成 UiState。适配器不修改目标结果、生命和集合，不缓存旧 Context。UISystem 最多每秒查询 5 次，并在初始化和阶段变化时立即查询；隐藏再显示会重新查询。目标确认后仍由目标系统调用 Core 的公开结果入口，UI 不自行 ReportResult。
