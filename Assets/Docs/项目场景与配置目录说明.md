# 项目场景与配置目录说明

更新日期：2026-10-28

本文根据当前场景、Build Settings、Bootstrap 序列化引用、配置资产和运行时代码记录 `Assets/Game/Scenes/` 与 `Assets/Game/Configs/` 的用途。它是静态代码/资产盘点，不等同于 Play Mode 或 Player 构建验收。

## 场景

| 场景 | 用途 | Build Settings / 入口 |
|---|---|---|
| `Bootstrap` | 持久化 `GameRoot`、`LevelManager`，注册配置与角色 Prefab | Build Settings 第一个启用场景；`BootstrapMenuLoader` 随后加载 `MainMenu` |
| `MainMenu` | 主菜单与关卡选择 | 已启用；`ReferenceMainMenuView` / `MainMenuLevelEntry` 可进入 `FirstLevel` 或 `Castle` |
| `FirstLevel` | 正式第一关 | 已启用；当前 `CFG_Level_FirstLevel` 选择护送武器目标 |
| `Castle` | 城堡关 | 已启用；当前 `CFG_Level_Castle` 选择护送武器目标 |
| `Level_test` | 旧护送武器和系统联调场景 | Build Settings 中禁用；代码保留测试入口，但当前主菜单不提供此入口 |
| `FirstLevel_CaveLegacy_Test` | 旧洞穴版本备份 | 未登记为 Build Scene；按项目决定保留 |

Build Settings 当前启用的场景只有 `Bootstrap`、`MainMenu`、`FirstLevel` 和 `Castle`。`Level_test` 与 `Assets/Game/Tests/AIBranches/Scenes/` 下的 14 个 AI 分支测试场景均已禁用；后者留在测试目录，不属于正式关卡。

`ProjectSettings/ProjectSettings.asset` 还保留 Unity 模板字段 `templateDefaultScene: Assets/Scenes/SampleScene.unity`。该字段指向旧模板目录，不是 Build Settings 条目，也不指向已删除的 `Assets/Game/Scenes/SampleScene.unity`。

## 配置

| 目录 | 内容 |
|---|---|
| `Campaign/` | 跨关卡继承的战役资源配置；由 `Bootstrap` 的 `campaignResourceConfig` 单独引用 |
| `Levels/FirstLevel/` | 正式第一关 `LevelConfig` |
| `Levels/Castle/` | 城堡关 `LevelConfig` |
| `Levels/LevelTest/` | `Level_test` 的关卡、胜负目标和护送武器配置 |
| `Levels/Legacy/` | 与旧洞穴备份配套的历史关卡配置 |
| `Actors/` | 史莱姆、敌人和守卫的角色配置；由多个场景共用 |
| `Maps/FirstLevel/` | 第一关地图定义 |
| `Maps/Castle/` | 城堡地图定义 |
| `Mechanisms/PlayerPlaceable/` | 玩家可放置的食物、熔炉和障碍配置 |
| `Mechanisms/Hazards/` | T1–T5 陷阱和补给点的设计参数 |
| `Status/` | 状态效果配置 |

`Bootstrap.LevelManager.levelConfigs` 当前序列化了 19 个 `ConfigAsset`，包括关卡、角色、Objective、护送武器、食物、熔炉、障碍、状态和旧洞穴关卡配置；`CampaignResourceConfig` 由独立字段引用。`Mechanisms/Hazards/` 下的 T1–T5 和补给配置没有出现在该注册列表中，当前运行时代码也没有读取 `FirstLevelHazardConfig`。第一关的地刺触发器由 `FirstLevelCompositionRoot` 按地图点创建，伤害间隔和比例目前写在 `TrapDamageAuthoring` 中；配置资产本身不会驱动这些效果。

## 当前配置值与代码差异

- `CFG_CampaignResources`：开局史莱姆 8/上限 20、食物 60/上限 60、熔炉 3/上限 10、障碍 5/上限 15；食物增殖关闭。重开本关时 `CampaignResourceLedger` 恢复入关快照，奖励按配置的关卡 ID 只领取一次。
- 同一配置将奖励 ID 写为 `FirstLevel`、`SecondLevel`、`ThirdLevel`，而当前第二关 `CFG_Level_Castle` 的 `LevelId` 是 `Castle`。奖励按 ID 精确匹配，因此 Castle 当前不会命中 `SecondLevel` 奖励；这是待修复的配置差异。
- `CFG_Level_FirstLevel` 与 `CFG_Level_Castle` 的 `objectiveKind` 均为 `EscortWeapon`，`maximumActivePlacedMechanisms` 均为 20。旧洞穴配置选择 `CaveOccupancy`；`Level_test` 未序列化 `objectiveKind`，会使用代码默认的 `CaveOccupancy`。
- `LevelContext` 根据 `LevelConfig.ObjectiveKind` 创建 `LevelResultRules`，但目前没有把 `ObjectiveConfig` 的规则字段传给结果规则。洞穴目标数量 6、等待 10 秒来自 `LevelResultRules` 构造器默认值；`ObjectiveConfig` 目前用于注册校验，不参与运行时结果计算。
- 地图配置为第一关和 Castle 分别提供 20 个编号史莱姆出生点；关卡组合按战役史莱姆数量从前往后取点。守卫围绕武器的偏移位置保存在共用 `CFG_Guard`。

## 引用与维护规则

- `Bootstrap` 场景中的 `LevelManager` 通过序列化的 `levelConfigs` 列表注册配置；文件放进某个目录本身不会让运行时自动加载它。
- `.asset` 移动时保留原 `.meta`，以维持 Unity GUID 和场景、Prefab、配置之间的序列化引用。
- 测试构建器中使用的 `AssetDatabase.LoadAssetAtPath` 路径已同步到新目录。
- 新配置按所属领域放入上述目录；关卡专属目标/武器规则归入 `Levels/<关卡>/`，多个关卡共用的角色数据归入 `Actors/`。

## 配置维护规则

- 配置只会由 `Bootstrap` 中的序列化引用注册；文件放入某个目录不代表运行时已加载。
- `.asset` 移动时保留原 `.meta`，以维持 Unity GUID 和场景、Prefab、配置之间的序列化引用。
- 新配置按所属领域放入上述目录；关卡专属目标/武器规则归入 `Levels/<关卡>/`，多个关卡共用的角色数据归入 `Actors/`。
