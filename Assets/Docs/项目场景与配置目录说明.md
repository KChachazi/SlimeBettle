# 项目场景与配置目录说明

更新日期：2026-10-20

本文记录 `Assets/Game/Scenes/` 与 `Assets/Game/Configs/` 的当前用途、配置归类和运行时引用边界。

## 场景

| 场景 | 用途 | Build Settings / 入口 |
|---|---|---|
| `Bootstrap` | 持久化 `GameRoot`、`LevelManager` 和全局预制体/配置注册 | 已登记，是启动入口 |
| `MainMenu` | 主菜单 | 已登记；当前菜单关卡入口仍会进入 `Level_test` |
| `FirstLevel` | 正式第一关 | 已登记 |
| `Castle` | 正式第二关城堡 | 已登记 |
| `Level_test` | 旧护送武器和系统联调场景 | 已登记，且仍由主菜单入口使用；保留作开发回归场景 |
| `FirstLevel_CaveLegacy_Test` | 旧洞穴版本备份 | 未登记为 Build Scene；按项目决定保留 |

未使用的 `SampleScene` 模板场景已删除。`Assets/Game/Tests/AIBranches/Scenes/` 下有 14 个 AI 分支测试场景；它们不归入正式场景目录，但目前仍启用在 Build Settings 中。本次未改动 Build Settings。

`ProjectSettings/ProjectSettings.asset` 还保留 Unity 模板字段 `templateDefaultScene: Assets/Scenes/SampleScene.unity`。该字段指向旧模板目录，不是 Build Settings 条目，也不指向已删除的 `Assets/Game/Scenes/SampleScene.unity`。

## 配置

| 目录 | 内容 |
|---|---|
| `Campaign/` | 跨关卡继承的战役资源配置 |
| `Levels/FirstLevel/` | 正式第一关 `LevelConfig` |
| `Levels/Castle/` | 城堡关 `LevelConfig` |
| `Levels/LevelTest/` | `Level_test` 的关卡、胜负目标和护送武器配置 |
| `Levels/Legacy/` | 与旧洞穴备份配套的历史关卡配置 |
| `Actors/` | 史莱姆、敌人和守卫的角色配置；由多个场景共用 |
| `Maps/FirstLevel/` | 第一关地图定义 |
| `Maps/Castle/` | 城堡地图定义 |
| `Mechanisms/PlayerPlaceable/` | 玩家可放置的食物、熔炉和障碍配置 |
| `Mechanisms/Hazards/` | T1–T5 陷阱和补给点的设计参数 |
| `Status/` | 状态效果配置 |

`Mechanisms/Hazards/` 中的资产目前只保存设计参数，没有注册到当前运行时配置表，也不会自行触发陷阱或补给效果。后续接入这些玩法时，需要由关卡组合把相应 `ConfigAsset` 注册到 `ConfigRegistry`。

## 引用与维护规则

- `Bootstrap` 场景中的 `LevelManager` 通过序列化的 `levelConfigs` 列表注册配置；文件放进某个目录本身不会让运行时自动加载它。
- `.asset` 移动时保留原 `.meta`，以维持 Unity GUID 和场景、Prefab、配置之间的序列化引用。
- 测试构建器中使用的 `AssetDatabase.LoadAssetAtPath` 路径已同步到新目录。
- 新配置按所属领域放入上述目录；关卡专属目标/武器规则归入 `Levels/<关卡>/`，多个关卡共用的角色数据归入 `Actors/`。

## 本次清理记录

- 删除 `Assets/Game/Scenes/SampleScene.unity` 及其 `.meta`：不在 Build Settings，也没有活动场景加载或 Prefab/场景 GUID 引用。
- 保留 `FirstLevel_CaveLegacy_Test` 及其配置，作为旧洞穴场景备份。
- 保留未接入运行时的陷阱/补给配置，因为它们仍是文档记录的首关设计数据。
- 其余配置均保留，按战役、关卡、角色、地图、机关和状态归类。
