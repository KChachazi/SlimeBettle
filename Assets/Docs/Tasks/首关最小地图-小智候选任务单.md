# 首关最小地图候选任务单：小智


依据：`Assets/Docs/SlimeBettle设计文档-3.docx`、`项目架构.md` 0.5、`16-MapManager.md`、`17-MovementSystem.md`
目标：完成首关地形事实、地图边界、固定运输路线和移动执行验证，不负责 Actor/机关/放置逻辑

## 1. 任务目标

为明天策划提供的第一关草图建立可被程序测试的地图事实：

- 正式记录地形、地图边界、出生点、敌人点、武器点和指定终点；
- 提供可查询的固定运输路线点，按稳定顺序包含终点；
- 使用现有 `MovementSystem` 执行普通 Actor 的直线移动，并为护送武器提供经接口评审后确认的路线分段移动适配；
- 保留静态碰撞和地形移动修正边界；
- 首关不实现动态网格寻路，不把固定路线误称为通用寻路；
- 为网格放置提供地图边界和坐标事实，但不实现 `PlacementSystem` 的预览或合法性规则。

首关不配置寒冷/炙热玩法效果；地形属于首关范围，但具体地形类型、倍率和进入/离开效果仍以系统设计文档和策划草图为准。

## 2. 前置依赖

1. 等待策划草图，确认路线点、终点、地形区域和静态障碍的几何位置；
2. 使用已确认的 `MapManager` 空间查询和 `MovementSystem` 移动接口；
3. 向小茶提供只读 `MapRouteSnapshot` 和运输位置/阻挡事实，不暴露可写场景组件；
4. 向小宸提供地图边界和世界坐标语义，避免 UI/放置层自行推导边界。

路线被玩家障碍占用后的行为尚未确认。本任务只能发布阻挡事实，不能私自选择“自动绕行”“忽略障碍”或“阻挡即失败”。第一张测试草图在规则确认前应避免默认障碍压在运输路线关键节点上。

## 3. 允许修改的目录

- `Assets/Game/Scripts/World/Map/`
- `Assets/Game/Scripts/World/Movement/`
- 与地图/路线配置直接相关的 `Assets/Game/Scripts/Data/Config/`
- `Assets/Game/Tests/` 下独立的地图、地形、碰撞和固定路线测试夹具/测试场景

## 4. 不允许修改的目录或资产

- `Assets/Game/Scripts/Actors/`、`Assets/Game/Scripts/Mechanism/`：不改 Actor、守卫或武器内部实现；
- `Assets/Game/Scripts/Player/`、`Assets/Game/Scripts/UI/`：不改输入、网格预览、UI；
- `Assets/Game/Scripts/Core/`：不改结果规则和关卡生命周期；
- `Assets/Game/Scenes/Level_test.unity`、Bootstrap、MainMenu 和其他正式场景；
- `ProjectSettings/EditorBuildSettings.asset`。

## 5. 公开接口边界

可以维护或实现以下地图/移动边界，但新增签名必须先登记到 `99-全局API查询表.md`：

- `MapManager.TryGetMapBounds(...)`；
- `MapManager.Query(...)`、`TryGetMapPoint(...)`；
- 候选的 `MapManager.TryGetRoute(MapRouteId, out MapRouteSnapshot)`；
- `MapManager.GetMovementSpeedMultiplier(...)`、静态阻挡查询；
- `MovementSystem.SubmitMovement(...)`、取消、移动状态和接触结果；
- 非 Actor 护送武器的运输移动适配（签名待确认）；
- `MovementBlockedEvent`。

不得由地图系统创建或销毁史莱姆、守卫、敌人、武器、机关或结果组件；不得通过读取其他系统私有字段判断路线运输状态。

## 6. 交付物

1. 首关地图边界、地形、出生点、目标点、武器点和敌人点的 authoring/查询方案；
2. 固定路线的稳定 ID、有序路点和终点表达；
3. 地形移动修正接入 MovementSystem 的最小验证；
4. 静态碰撞和越界查询的 EditMode/PlayMode 测试；
5. 固定路线查询和分段移动的测试夹具；
6. 一份面向场景作者的草图标注约定：视觉地形、静态碰撞、路线节点、可放置区域分别如何表达；
7. PR 描述中的验证层级：编译、EditMode、PlayMode、人工运行和未验证项必须分开写。

## 7. 验收标准

- 同一关卡中边界、路线 ID、路点 ID 和地图点 ID 可诊断且稳定；
- `MapManager` 能返回固定路线的有序路点和终点，路线查询不执行动态寻路；
- 普通 Actor 仍由 MovementSystem 直线移动，静态阻挡产生 `MovementBlockedEvent`；
- 地形移动倍率通过 MapManager → MovementSystem 生效，不修改 Actor 基础配置；
- 网格放置可获得地图边界，但 MapManager 不直接创建放置对象；
- 暂停、重开和 Dispose 后不会保留旧地图索引、区域成员和路线引用；
- 不修改正式场景、Build Settings、Actor/Mechanism/Player 内部实现。

## 8. 并行和合并顺序

- 与小茶：先完成路线快照和移动事实契约，再并行开发武器固定路线适配；
- 与小宸：先提供边界和坐标事实，小宸在自己的测试场景中验证网格映射；
- 合并建议：地图/路线查询与测试 → Mechanism 固定路线运输 → Placement/Grid 适配 → 首关场景装配；
- 地图 PR 不应把正式关卡草图直接写入 `Level_test`，除非另行确认场景整合任务。

## 9. 必须回报的问题

- 草图中的哪些区域是纯视觉地形、静态碰撞、可通行路线或不可通行区域；
- 固定路线是否允许经过会被玩家放置障碍的格子；
- 地形倍率和边界坐标单位；
- 路线被阻挡时 MovementSystem 只报告停止，还是需要 MechanismSystem 继续管理等待状态。
