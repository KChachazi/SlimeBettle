## 本次新增契约（先通知，再提交实现）

- Player.Placement.PlacementGridAuthoring 使用场景 Unity Grid 的原点、单元尺寸和变换，在 XY 平面进行 WorldToCell / GetCellCenter；场景作者必须明确配置，隔离测试的单位格只是测试值。
- PlacementSystem 提供 BeginPlacement(PlacementItemId)、PreviewPlacement(Vector3)、ConfirmPlacement()、CancelPlacement()、GetCurrentPreview()、GetBudgetSnapshot()，只维护模式、预览和单格占用，不生成机关。
- PlacementItemId 仅 None / Food / Furnace / Obstacle。预览区分空闲、已占用、越界、无坐标、未绑定依赖。最终确认重新检查阶段、地图边界和占用。
- IPlacementBackend 由机关负责人/关卡组合层实现：公开请求输入 PlacementRequest（类型、格子和世界中心），返回 PlacementResult；ReadPlacedObjects 返回只读 ID/位置，GetBudgetSnapshot 无数据时返回未配置状态。请求失败不得创建占用；对象消耗/拆除后通过快照重建占用。
- 确认后的单次/连续模式使用显式 PlacementConfirmationMode 配置，场景接入方选择，隔离测试覆盖两者。首关次数、冷却和总上限不由 UI 或放置层硬编码。
- PlacementInputAdapter 只消费已有输入事实并投影；点击地图锁定世界格子，再次点击地图更换目标，移向确认按钮或移动镜头不改变已选格子。选格前仍支持悬停预览；取消、重新选择、暂停、失焦和重开清除锁定。PlacementGridView 只显示网格、预览和占用，PlacementSelectionView 只提交三种选择/确认/取消。
- UiState 尾部增加可选 SlimeLimit / WeaponText，现有构造调用保持兼容。FirstLevelUiSnapshotSource 查询公开史莱姆快照，IFirstLevelStatusSource 适配武器/结果的只读显示数据。缺少新接口时显示未接入，不从旧 ObjectiveSystem 复制武器数据或推断胜负。
- FirstLevelPresentationRoot 显式组合当前 LevelManager、InputSystem、CameraSystem、Grid、PlacementBackend 与状态来源，使用 MapManager.TryGetMapBounds；阶段变化、取消、失焦、禁用、卸载清理选择与预览。重开绑定新关卡实例。

## 当前实现与接入约束

代码位于 `Assets/Game/Scripts/Player/`（命名空间 `SlimeBattle.Player.Placement`）和 `Assets/Game/Scripts/UI/`。测试入口和操作步骤见 `Assets/Game/Tests/PlayerPresentation/FirstLevelPlacement-README.md`。

- `PreviewPlacement` 返回 `PlacementValidationResult`，含 `Preview / IsValid / Reason`；`ConfirmPlacement` 返回 `PlacementResult`，含 `Succeeded / MechanismId / Reason`。确认按钮显式提交，地图 PrimaryAction 更新并锁定目标格，不创建对象；这一交互方式可评审，不把单次／连续模式当成已确认正式规则。锁定只在输入适配器内管理，公开预览／确认接口仍使用调用方提供的位置，签名与结果契约不变。
- 格子吸附使用 Unity Grid 的向下取整（包括负坐标），中心位于 Grid 的 XY 平面。原始指针点和吸附中心都必须在 `MapBounds` 内；不完整边缘格不会因吸附而允许越界点击。占用仅来自后端快照中的有效玩家对象 ID，不扫描 Actor 或武器。
- 后端契约为同步请求：返回成功时必须提供有效 ID，并已能从 `ReadPlacedObjects()` 查询到该对象。只有当前关卡实例的玩家放置对象进入快照，移除／消耗对象不再返回。若未来改为异步，需要先评审请求 ID、取消与晚到结果的接口，不能直接返回暂定成功。
- `Changed` 是本地只读视图刷新事件，`PlacementCompleted` 是本次尝试的结果通知；当前不伪造 `LevelEventBus` 上的机关创建、武器或胜负事实。正式领域事实仍由对应所有者确认。
- `FirstLevelPresentationRoot.Initialize(...)` 的 backend 只绑定调用时的 `LevelContext`。新关卡 `LevelStarted` 后重建放置状态，旧 backend 不会复用；组合方须为新 Context 再次注入新 backend，否则使用只读降级适配并拒绝正式创建。状态来源每次接收当前 Context，禁止缓存旧关卡对象。
- `PendingMechanismPlacementBackend` 只读取当前公开机关快照，`IsAvailable == false`，不创建或实例化正式机关；缺少地图或后端时预览为 Unavailable。
- HUD 查询 `SlimeManager.GetAliveSnapshots()` / `MaxAliveCount`，显示真实数量和配置上限。若上限不是 20，明确提示配置差异；当前 master 默认上限仍是 30，需配置负责人统一首关 `LevelConfig`，显示层不将 30 伪装为 20。
- 独立 GridView 的网格线和占用显示可复用；取消、暂停、结算与禁用时销毁预览对象，卸载时销毁所有自有视图资源。最多绘制每轴 256 格线与 512 个占用色块，仅为显示预算，不限制正式放置数量。
