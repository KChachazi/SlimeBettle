# 第二关城堡实现与接入

## 数据来源与坐标

城堡地图事实来自 `C:\Users\37935\Desktop\数据\城堡` 中的道路 CSV、出生/刷怪点文本和机关位置说明。地图按 5760×5760 像素、左下角为原点录入，并沿用项目暂定比例 `100 px = 1 Unity unit`。未从截图或素材推测道路和机关位置。

`MAP_Castle.asset` 记录 12 个道路矩形、史莱姆出生点 `(2926, 244)`、敌人刷怪点 `(2938, 3549)` 及终点 `(2908, 4873)`。玩家移动和放置都通过 `MapManager` 校验这些道路；放置还会避开当前启用的地刺碰撞体。场景视图可以查看地图道路、点位和护送路线的 Gizmos。

护送目标使用现有 `mvp_escort_weapon` 配置，并按确认的直线路线抵达 `(2908, 4873)`。史莱姆与武器都在来源数据给出的出生点 `(2926, 244)` 开始，和第一关一样从护送路线起点进入载具范围。守卫坐标未在来源文件中单独标出，按确认的“在出生点附近偏移”放置于右侧 `(3046, 244)`；该位置处在中央主通道内。餐车保持装饰用途，没有用作武器或路线节点。关卡目标使用与第一关相同的护送武器到终点判定。

## 美术与机关

- `IMG_Castle_Background`、`IMG_Castle_Floor` 和 `IMG_Castle_WallOcclusion` 分别绘制背景、组 1 地面和组 14 遮挡层。组 1 尺寸为 5760×5547，底边与地图底边对齐，顶端保留 213 像素透明缺口；组 14 铺满 5760×5760，并置于角色上层。
- 参考 `城堡总览.png` 将独立素材按原图像素位置接入地图预制体：餐车轨道、餐车、城门、铁门、宝箱和拉杆。餐车和餐车轨道仅作装饰；未给它们添加碰撞或机关逻辑。
- 地刺和按钮按机关位置表中的矩形中心/尺寸摆放。按钮排序在角色下方，角色经过时不会被按钮图覆盖。
- 地刺是静态阻挡碰撞体；史莱姆进入对应按钮触发区后，该按钮关闭对应地刺。按已确认范围，首版没有添加伤害效果。
- 护送中的史莱姆碰撞体会被系统关闭；按钮还会检测其可见身体是否进入按钮区域，避免武器被地刺挡住时无法压下按钮。

## 运行入口

新增 `Castle` 场景及 `CFG_Level_Castle` 配置，已登记到 Bootstrap 的配置列表和 Build Settings。主菜单第二张关卡卡片会进入城堡场景。场景组合根从地图点生成一只史莱姆和一只普通敌人，并绑定地图约束的随机游走感知；守卫由护送目标系统按地图守卫点生成。

城堡的感知组合沿用第一关的食物/热源引导接入。史莱姆出生事件会立即尝试载具判定，避免首个物理步先将重叠的史莱姆与武器推开；上车后局部位置固定为 `(0, 0, 0)`。守卫会跟随移动中的武器目标，状态机在目标移动不足 `0.2` Unity 单位时沿用当前移动请求，避免每帧撤销并重发导致跟随停滞。宝箱、拉杆、门体目前只显示原图素材，没有添加互动逻辑。未运行 Unity 场景或测试。
