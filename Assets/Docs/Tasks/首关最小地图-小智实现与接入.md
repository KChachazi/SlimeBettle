## 当前差异中的既有实现汇总

以下是本任务前几轮工作区差异中的代码和资产实现，合并记录在此，便于按工作区差异追溯。

### MapManager 与地图模型

- MapLayoutAuthoring 绑定 FirstLevelMapDefinition；定义负责从 5760 像素坐标构造 MapLayoutSnapshot，其内容包含边界、圆形区域、地图点、路线和 Anchor。MapManager 增加从此快照绑定数据的路径，并允许离线圆形区域参与 Query、区域中心与地形倍率查询。
- 加入 MapAreaKind.Goal；扩充地图点类别（守卫出生、补给、教程、分叉/合流、终点、机关等），地图点快照增加像素交互半径，Authoring 对负值、NaN 和无穷值报告错误。
- 路线快照增加 Candidate/Branch/Main 角色、合流点 ID、阻断 Anchor、关联地图点和终点访问器。分支不能标记 Goal，必须落在有效 Merge 点；Manager 检查分支终点坐标和合流点相同、合流点出现在共享主线上，并检查路点/关联 ID 有效。
- 新增 Anchor ID、角色、快照和 Authoring。MapManager 提供按 ID 查询和批量只读查询；Anchor 保存允许机关种类、替换策略、吸附距离及关联路线/地图点。
- 对外查询 API 包括 `TryGetMapBounds`、`Query`、`GetMovementSpeedMultiplier`、`TryGetMapArea` / `TryGetMapAreaCenter`、`TryGetMapPoint` / `GetMapPoints`、`TryGetRoute`、`TryGetPlacementAnchor` / `GetPlacementAnchors`、`CanOccupy`。路线/Anchor 快照为只读数据。
- 地图边界/路线/点/Anchor 的越界、重复 ID 和缺失关联在场景绑定时输出诊断。MapLayoutAuthoring 与 MapBoundsAuthoring 同场景并用会报错，避免重复定义边界。

### 首关地图和机关配置

- MAP_FirstLevel.asset 录入 DOCX 边界、出生/敌人/陷阱/补给/教程/分叉/合流/终点点位，三条分支路线和共享主线，以及六个 Anchor。路线点顺序按 DOCX 保存。
- 终点区域半径 400px；T4 沼泽、T5 峡谷附近当前分别使用半径 130px 和 140px 圆形代理，地图倍率均为 1。T4 的 0.5 倍移速、3 秒效果单独保存，防止以后 MapManager 地形倍率与 StatusManager 效果重复生效。
- FirstLevelHazardConfig 保存并校验首关陷阱/补给静态规则。T1/T2：半径 120px、伤害 80、冷却 1.5 秒；T3：一次滚石、触发半径 140px、伤害 120、击退 400px、投射物半径/速度/行程 60px/900px·s⁻¹/800px；T4：半径 130px、0.5 倍、3 秒；T5：半径 140px、一次伤害 150 并返回安全边缘；补给：半径 60px、一次领取 4 个。
- MechanismConfig 新增库存、耐久、碰撞半径字段及校验。Food 吸引半径改为 400px，Prefab 圆碰撞半径 0.4 world unit（40px）。Furnace 沿用现有 500px 默认值。Obstacle 设置库存 10、耐久 3、放置冷却 1 秒、半径 55px / 0.55 world unit，并将障碍 Prefab 碰撞改为圆形。
- 陷阱/补给规则仍是静态数据，没有触发器、投射物、伤害/状态结算或拾取运行时；相关 ConfigAsset 还需关卡组合时注册到 LevelConfig/ConfigRegistry。
