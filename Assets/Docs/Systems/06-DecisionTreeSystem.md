# 06 DecisionTreeSystem 决策树系统设计

系统编号：`AI-01`  
系统名称：`DecisionTreeSystem`  
默认命名空间：`SlimeBattle.AI.DecisionTree`  
建议实现目录：`Assets/Game/Scripts/Slime/`  
生命周期：由具体角色系统创建和销毁  
状态：核心架构，节点内容依据当前策划方案继续细化

## 1. 职责

- 驱动单个角色的主动感知和决策；
- 从 `DecisionContext` 读取自身状态、环境查询和上一次行动结果；
- 按节点顺序选择一个行动意图、等待或目标切换结果；
- 在目标无效、环境变化或行动失败时重新评估。

本系统只负责“决定下一步做什么”，不负责执行动作。

## 2. 不负责的内容

- 不直接写入角色位置、生命和状态；
- 不执行攻击命中、击退和机关效果；
- 不替代状态机处理行动过程和中断；
- 不向所有角色广播感知结果。

## 3. 核心类型

```text
DecisionTreeRunner
DecisionNode
DecisionContext
DecisionResult
ActionIntent
TargetHandle
```

`ActionIntent` 是决策树和状态机之间的边界对象。具体行动类型，例如移动、攻击、排队和等待，待策划方案确定后扩展。

## 3.1 当前史莱姆决策方向

以下内容是当前策划方案对决策树的输入约束，不等于已经确定的节点类：

- 个体优先感知“进食、取暖、躲避危险”等本能需求，再根据敌人、目标和环境决定是否移动或战斗；
- 食物、熔炉和其他引导源可以成为目标；存在多个可用引导源时，当前图示提出随机选择；
- 史莱姆遇到魔物后具有战斗意图；生命值低于 50% 或 30% 时，图示提出不同概率的逃避战斗判定，并可能进入害怕状态；
- 史莱姆群体形成后，个体决策需要把群体目标、队列/阵型和群体策略作为上下文；个体被其他需求吸引并改变目标时，应把“离开群体”作为行动结果；
- 暴躁状态下允许把附近人类单位纳入攻击目标；战斗状态下通常不受普通引导源影响，但饥饿或寒冷等需求可能重新获得优先级。

正文写的是“超过 90 秒未进食后，每 10 秒有 20% 概率变为暴躁”，图示同时出现 90/120/150 秒的分段规则。这里先保留为待确认的决策条件，不在决策树接口中固化具体阈值。

## 4. 必须接口

```csharp
void SetRoot(DecisionNode root);
DecisionResult Evaluate(DecisionContext context);
void Reset();
void Stop();
```

`Evaluate` 只返回决策结果，不直接调用移动、战斗或机关系统。

## 5. 对外事件

决策树默认不向全局 EventBus 发布每次思考事件。调试模式可以提供只读诊断数据，但不应让 UI 或玩法逻辑依赖“思考完成”事件。

## 6. 依赖

- `ActorCore` 的角色快照；
- `MapSystem` 的空间查询；
- `MovementSystem`、`CombatSystem` 和 `PassageSystem` 的结果快照；
- 所属角色系统提供的决策上下文。

## 7. 关键不变量

1. 决策树不能直接修改任何其他系统的数据。
2. 相同上下文和相同输入应得到可解释的结果；随机性必须由上下文明确提供。
3. 角色死亡、暂停和关卡重开时，决策树必须停止并清理引用。

## 8. 待确认项

- 节点类型和节点资产是否数据化；
- 感知频率和每帧决策上限；
- 是否需要随机权重、优先级或冷却节点；
- 是否为不同角色共享部分决策树。
